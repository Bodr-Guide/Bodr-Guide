## 체계적 디버깅

$ARGUMENTS 문제를 4단계 프로세스로 디버깅하세요.

### 4단계 프로세스

1. **재현** — 버그를 안정적으로 재현
   - 에러 메시지, 스택 트레이스 확인
   - 재현 가능한 최소 조건 파악
2. **원인 분석** — 근본 원인(root cause) 추적
   - 관련 코드 읽기, 로그 분석
   - 가설을 세우고 검증
3. **수정** — 최소한의 변경으로 수정
   - 근본 원인만 수정 (증상이 아닌 원인)
   - 사이드 이펙트 확인
4. **검증** — 수정 확인 및 회귀 방지
   - 버그 재현 시도하여 수정 확인
   - 회귀 테스트 작성

### 규칙

- 추측으로 코드를 수정하지 않음
- 한 번에 하나의 변경만 적용하여 효과 확인
- 수정 후 반드시 테스트로 검증
